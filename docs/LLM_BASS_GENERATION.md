# LLM 直接编排贝斯实验

## 网页试听

在「文字创作 → 高级设置 → 音符编排」选择「LLM 直接编排贝斯」。先用「来一段」试听开场，也可以把「文字处理」设为大模型 Agent，再要求具体的贝斯音域或音符走法。网页模式支持 1–4 小节。没有已采纳的节奏输入时，模型可以选择贝斯起音。已有节奏锚点时会保留锚点。

开场创作或获 BandPlan 授权的贝斯改写会调用直接编排。校验失败或本轮计划未授权时沿用规则版本，页面显示回退状态。展开「音符编排日志」可看到本轮结果及回退原因。生成的贝斯音符写入当前段落的 MIDI 和 WAV，后续段落仍从共同的 JamState 生成。

## 离线实验

实验在现有离线渲染入口中注入 `LLMBassArranger`。LLM 读取当前用户请求、BandPlan、速度、调性、每小节的和弦与节奏锚点，以及固定主旋律，直接为两小节贝斯生成完整音符表。模型输入中没有规则贝斯的音符。鼓、键盘和主旋律沿用现有编排。

模型输出包含 `bar`、`step`、`length_steps`、`pitch` 和 `velocity`。小节从 0 开始，每拍分成四格。程序检查音域、调性、整拍的和弦音、节奏锚点、越界和重叠。实验用严格模式，校验失败时记录拒绝，保留原始模型回复，避免把规则回退算成模型成功。原型也支持规则回退。

## 对照结果

固定 100 BPM、C 大调、C 与 G 两个小节，并保留每小节起点后的 0、1.5 和 3 拍。每组 A/B 改一项文字要求，分别测试纯规则、现有 LLM 微调、LLM 直接编排，使用同一份乐段状态与固定 BandPlan。每组重复两次。读回导出的 MIDI，当 A、B 都达到对应目标且鼓、键盘、主旋律与基线逐音符一致时，计这对通过。

| A/B 测试 | 纯规则 | LLM 微调 | LLM 直接编排 |
| --- | ---: | ---: | ---: |
| 第二小节句尾加 1 个 / 2 个短音 | 0/2 | 0/2 | 1/2 |
| MIDI 音域 36–47 / 48–59 | 0/2 | 0/2 | 2/2 |
| 时值 0.25 / 0.50 拍 | 0/2 | 0/2 | 2/2 |
| 根–根–根 / 根–五度–根 | 0/2 | 0/2 | 2/2 |
| 合计 | 0/8 | 0/8 | 7/8 |

实际 API 返回的模型版本为 `gpt-5.4-mini-2026-03-17`。直接编排共调用 16 次，14 个变体通过并渲染，编排耗时中位数为 4.73 秒。两次拒绝都来自句尾测试的第一轮，模型把非和弦音放在了整拍。第二轮的句尾 A/B 在保留原来六个锚点的基础上，分别新增了 1 和 2 个音。微调的可用操作包含调整力度、时值、起点或删音。本次固定的 BandPlan 也限制了微调修改节奏锚点，且微调本身不支持新增音符或指定音高。表中分数衡量这些具体请求的实现能力。

另做了一次事后检查，将 A/B 明确要求变化的贝斯属性从比较中移除。七对通过的直接编排结果中，所有对子仍有其他贝斯属性随请求变化，例如力度。这组数据来自早期两小节原型和当时的提示词。

## 复现

在仓库根目录用已有 JamMate API 配置运行。如果已设置 `JAMMATE_LLM_CONFIG`，可以省略 `--config`。

```bash
PYTHONPATH=src python examples/benchmark_bass_generation.py \
  --mode all --repeat 2 --jobs 3 --config "$JAMMATE_LLM_CONFIG" \
  --out demo_out/bass_generation_replay
```

输出目录需尚未存在。使用 `--mode rule` 可离线跑纯规则对照。每个变体保存输入、状态、计划、规则参考 MIDI、模型日志和校验结果。成功的变体还会保存 `band.mid` 和 `band.wav`。第二轮句尾试听在本地运行目录的 `02/tail/direct/`。 [实验汇总](../examples/benchmark_evidence/bass_generation_pilot.1sU7ab/results/report.json) · [事后检查](../examples/benchmark_evidence/bass_generation_pilot.1sU7ab/results/within-bass-audit.json)
