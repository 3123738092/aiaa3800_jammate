# JamMate 文字意图快路径

快路径放在文字事件登记之后、完整 LLM Agent 决策之前。它复用 `InputEvent`、`JamState`、`BandPlan` 和执行回执。简单指令可以由 Jev 选出意图和候选参数，再交给代码生成计划。要依赖完整历史、音乐创作或多步推理的请求继续交给现有 Agent。

## 一次请求里怎么提问

Jev 的 TypeSafe System One 接口支持在一份请求内并列多个有类型的问题。输入用本轮原话和紧凑的本轮状态，只附必要的历史状态或引用。通过 OhMyGPT 调用 `POST /v1/systemone`，使用该端点返回的模型 ID 记实验日志。 [TypeSafe 接口](https://api.typesafe.ai/redoc) · [OhMyGPT 决策接口](https://docs.ohmygpt.com/docs/api/decisions)

1. 让 Jev 判断整轮能否用现有计划表达，并识别明确冲突、需要深入解析的请求或能力限制。
2. 同时询问各类改动和约束。实际接入优先按计划字段拆分，例如速度语义、目标声部、动作方向、计划小节数、保护条件和是否有遗漏的其他要求。试验脚本先问路由、速度语义和声部范围三个问题。
3. 由代码从原文、受支持的声部和明确的历史条目中准备候选。候选包括被改口覆盖的旧值、原句里的数字及单位、当前活跃对象，以及无法确定的选项。保留数值的出处和单位，避免把「2 小节」或「力度增加 8」误当成 BPM。
4. 接纳候选前检查意图、数值范围、声部存在性、保护约束及执行能力。命中快路径时复用计划构建和执行校验，事务写回仍由 `StateManager` 负责。参数不齐、分数低、问题间矛盾、需要音符级处理，或还有未解释的请求时，整轮进入原 Agent。使用同一批事件和同一份状态快照，避免两条路径分别执行同一句中的不同分句。

「从当前速度再减 4 BPM」在 92 BPM 时得到 88，在 110 BPM 时得到 106。Jev 只需选中「相对减速，使用原文中的 4」，代码负责读当前速度、计算和生成 `BandPlan.transport.tempo_bpm`。「速度改回第 1 轮开始前」在能定位已提交历史时可由代码取回数值。找不到记录时继续让 Agent 澄清。

## 覆盖范围和验收

| 输入 | 可以尝试的路径 | 验收 |
| --- | --- | --- |
| 绝对与相对 BPM、指定长度、续奏、停奏 | 封闭的动作与类型化参数 | 计划 BPM、段落长度和提交位置正确 |
| 指定声部的音量、疏密、静音、恢复和木吉他 | 选择声部、操作与保护项 | 对照状态和 MIDI，确认目标声部和其余声部 |
| 中英混合、改口、否定、多动作 | 在同一请求内判断各轴，检查分句和保护条件 | A/B 只改变一个词或数字，检查变化方向、错误执行和改动遗漏 |
| 跨轮引用、已停奏会话、模糊对象 | 用受控的状态或历史引用；证据不足时走完整 Agent | 对照同一句话在不同历史的行为，检查错误恢复、意外复奏及澄清时是否推进小节 |
| 场景描述、单音符微调、完整重写贝斯、部分支持的混合请求 | 路由到完整 Agent 或对应编排器 | 检查有无把局部指令误执行成全声部改动 |

用现有 18 轮基准检查端到端回归，用 62 轮扩展基准覆盖中英混合、历史恢复、边界和澄清，另用固定计划的编排最小差异对照检查路由是否把音符级请求送到了正确阶段。这次的独立小样本覆盖相对与绝对调速、历史存在性、声部、音符请求和能力边界。调参时按会话或最小差异组划分开发集与保留集，成对输入留在同一个分组里。 [文字基准](TEXT_AGENT_BENCHMARK.md) · [62 轮扩展](../examples/text_benchmark/EXTENDED_CASES.md) · [音符编排基准](ARRANGEMENT_BENCHMARK.md)

主要指标是快路径错误执行率、字段与完整计划精确率、快路径覆盖率、回退率、状态与 MIDI 回归，以及分层 p50/p95 耗时。单独统计快路径、普通 LLM 和 Jev 后回退 LLM，避免把网关接口延迟和端到端生成耗时混为一项。Jev 的分数用于排序和设置候选阈值，阈值应根据 JamMate 样本上的实际误判来决定。

## 独立分类试验

测试器向 Jev 发送固定的人工标注场景，收集三个问题的选择与概率。它不生成计划或改动作品。报告中的置信度门槛是事后诊断，不能当作生产阈值。

首轮使用 OhMyGPT 返回的 `jev-1.14.0`，42 次请求均成功。路由正确 36/42，速度语义和数字候选正确 39/40，声部范围正确 35/38，所有标注字段同时正确 33/42。四组并发下单次网关请求的 p50 为 846 ms，p95 为 983 ms。耗时只覆盖分类请求。 [逐条基准与概率](../examples/benchmark_evidence/jev_classifier_pilot/pilot.json)

- 阈值设为 0.95 时，有 12 条被判入快路径，其中 10 条所有标注字段匹配。全队停奏被误标为多声部修改。当前 176 BPM 时的「再快 10 BPM」被以约 0.96 的置信度判为快路径。
- 回放上述超范围速度候选时，代码算出 186 BPM，现有 BandPlan 校验拒绝提交，JamState 保持 176 BPM。合法对照分别写回 92、88、106 BPM。四个回放用例只验证调速执行。 [计划与状态回放](../examples/benchmark_evidence/jev_classifier_pilot/tempo-application-check.json)
- 「提到 96 BPM，再改成 C 小调」被整体判成不可支持，漏掉了可执行的调速。因此生产接入要检查各分句是否被覆盖，再决定完整执行或交给 Agent。全队停奏与逐声部静音也需要单独约束。

```bash
python examples/text_benchmark/jev_probe.py --dry-run
python examples/text_benchmark/jev_probe.py --jobs 4 --out demo_out/jev_classifier_replay/pilot.json
```

真实运行从环境变量 `OHMYGPT_API_KEY` 读取凭据。报告保存输入、预期、选择、概率、实际模型和单请求耗时。选择一个新的报告路径。
