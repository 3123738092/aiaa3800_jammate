# JamMate 文字决策的分轮迭代

主对话确定每轮要验证的问题、负责实现和复核结果。每轮实验由一个独立子代理冻结用例、运行对照并保存逐条记录。现有 88 轮 Jev 旁路保留为前一阶段基准。 [原旁路实验](JEV_SHADOW_BENCHMARK.md)

第 3 轮及后续进展统一记录在 [文字决策迭代 TODO](CLASSIFIER_TODO.md)。

## Jev 与完整 LLM 的共用机制

| 步骤 | 完整 LLM | Jev 快路径原型 |
| --- | --- | --- |
| 登记输入 | 继续由 StateManager 登记原文，绑定状态版本 | 同一批事件和状态版本 |
| 确定意图 | 读取原话、当前状态和近期历史，提出完整计划 | 在有限候选中选操作与参数 |
| 核对原文 | 若全文是可精确解析的调速指令，检查计划是否兑现了目标，并保护播放状态和其他声部 | 将所选方向、数值与整句原文核对。遇到额外未解析分句、历史指代或错误候选便让出执行权 |
| 校验执行 | 计划仍有未完成项时，检查是否存在实际可执行的独立改动 | 候选编译成同一份 BandPlan，运行同样的校验 |
| 提交结果 | 可执行计划按原有机制在成功回执后写入状态。需要等待时保留当前小节 | 同样的执行边界 |

目前可直接核对的是明确的绝对速度、相对速度和封闭的有条件调速句式。程序计算实际 BPM 并执行 60–180 BPM 范围检查。可明确解释且超范围的请求生成保持计划，完整 LLM 路径无需发起模型请求。合法的空计划仍可续奏。实际的部分执行，例如调速并告知小号不支持，仍会执行其中可行的部分。网页与命令行共用执行前的等待判断。Jev 计划编译仍从实验入口调用。

## 第 1 轮：计划没改动时应该等还是续奏

对照了 18 个冻结用例，包括 14 个已归档的真实 GPT-5.4 Mini 计划和 4 个合成对照。使用 OfflineRuntime 真正渲染和提交允许执行的计划。旧网页条件通过 10/18，共用执行判断通过 17/18。六个归档失败修复了五个，两个新增的无实际改动对照也正确停止。正常空计划续奏、停奏后预设速度并恢复、有真实改动的部分执行均保留原行为。相同的减 4 BPM 请求从 92、110 分别得到 88、106。

剩下的 203 BPM 用例中，归档模型给了无未完成项的继续演奏计划。仅检查计划是否有未完成项，无法判断它漏掉了用户提出的限制。这就是第二轮增加原文和计划核对的原因。 [第 1 轮汇总](../examples/benchmark_evidence/classifier_iteration_20261119/round1/summary.json) · [逐条结果](../examples/benchmark_evidence/classifier_iteration_20261119/round1/cases.jsonl)

## 第 2 轮：把选中的调速参数绑定到原话

比较明确调速、边界值、改口、否定和多要求。验收分别看执行后 BPM、等待时下一小节是否保持、拒绝不一致的候选，以及复合请求是否完整交给 Agent。数值证据来自原文，后续轮的绝对目标使用当前状态计算。在多要求中只提取到速度时，候选按不完整处理。

本轮冻结 16 条成对用例与 1 条注入错误的 Jev 数字候选。两条路径均检查等待与退出时是否推进小节，并对可执行候选运行 OfflineRuntime。

| 结果 | Jev 快路径原型 | GPT-5.4 Mini 完整 Agent |
| --- | ---: | ---: |
| 达到各自的预设结果 | 17/17 | 15/16 |
| 真实执行并提交 | 9 | 12 |
| 确认等待 | 3 | 3 |
| 退出快路径 | 5 | — |
| 校验失败并保持状态 | 0 | 1 |
| API 决策耗时中位数 | 0.84 秒，16 次请求 | 3.85 秒，13 轮实际调用，14 次请求 |

两条路径都拦下 203 BPM、另一种说法的 199 BPM 和 176 + 10 BPM，并正确处理 92 → 88、110 → 106。完整 Agent 的三个明确超限请求在模型调用前等待，中位耗时 14.8 ms。Jev 的五次退出包含四条真实分类用例和一条人工错误候选。退出按快路径策略验收，后续由完整 Agent 处理。两个模式的通过率因此不能直接比较。

唯一未达到预设结果的完整 Agent 用例是「速度设到 96 BPM，同时让鼓停下来」。第一次回复一边静音鼓一边要求保留鼓点，第二次一边指定 96 BPM 一边要求保留原速度。校验拒绝了两份计划，状态和小节都没有推进。 [第 2 轮汇总](../examples/benchmark_evidence/classifier_iteration_20261119/round2/summary.json) · [逐条结果](../examples/benchmark_evidence/classifier_iteration_20261119/round2/cases.jsonl)

## 下一轮实验

先围绕已经观察到的混合调速和具名声部开关做对照。为每个分句记录原文依据、目标字段和约束。把「96 BPM + 静音鼓」和「保持速度 + 静音鼓」做成近邻配对，另测「继续用原来的鼓点」这一显式冲突。分别验收速度、鼓的激活状态、其余声部、下一小节位置，以及冲突或能力限制时是等待还是部分执行。

完整 LLM 实验要检查它能否生成互相兼容的修改和保护项。Jev 实验要检查它能否选齐每项候选，以及只选到其中一项时是否继续退出快路径。分句组合先通过，再把明确的段落长度放进同一个组合机制。保留新的同义表达作为独立评估集。
